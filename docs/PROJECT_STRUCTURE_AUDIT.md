## Safety checkpoint

The working tree was already **not clean** before this audit. It contains a large set
of modified tracked files and untracked application files from ongoing development.
No user changes were discarded, reset, checked out, or overwritten. `.env` files were
not changed.

Before a future cleanup commit, create a reviewable checkpoint commit or a separate
backup of the current worktree. Do not use `git clean`, `git reset --hard`, or
`git checkout .` on this worktree.

## Duplicate-code audit

- JWT creation, signing, expiry, and verification are centralized in
  `backend/security.py`.
- Bearer extraction and database-authoritative user/role checks are centralized in
  `backend/deps.py`.
- Frontend token access is centralized in `frontend/src/utils/authStorage.js`;
  `frontend/src/services/api.js` consumes that helper.
- Database engine/session creation is centralized in `backend/database.py`.
- Production live inference is in `backend/live_stream.py`; `ai/live_monitor.py`
  is a separate command-line monitor with its own CLI behavior.
- Email delivery has separate template/notification concerns, so the existing
  modules were not merged.

No automatic deduplication or refactoring was performed.

## `.gitignore` audit

Existing rules cover Python caches, virtual environments, Node dependencies/builds,
environment files, uploads, database dumps, AI weights/runs/datasets, logs and
editor files. The following narrow rules were added:

- `*.log` for reproducible local/package/runtime logs such as `pypdf-install.log`.
- Root `_ai1_*.txt`, `_baseline_p20.txt`, and `_p20_*` through `_p23_*` files
  for historical captured test/build output.
- `**/Ultralytics/settings.json` for Ultralytics-generated machine-specific settings.

`.env.example`, Dockerfiles, migrations, source code and required model/configuration
files remain eligible for version control. `.env` remains ignored and was not read
into this report.

## Secret audit

No committed secret value was identified. Code contains environment-variable names
for JWT, SMTP, Google, database and dataset-provider credentials, plus test
placeholders; these are configuration interfaces, not exposed secret values.
Secret values were not printed. Local `.env` files remain ignored. If a real
credential has ever been placed in a tracked or shared file, rotate it separately.
